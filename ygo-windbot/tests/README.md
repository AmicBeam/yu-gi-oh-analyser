# 双子终场规划对拍

普通起手、定向起手和手坑配对默认使用独立引擎搜索。双方使用同一份固定牌序和卡片脚本。生产侧在 SRVPro2 房间执行，参考侧每手从起手重新探索，通过决斗引擎实际执行每个响应。搜索根据引擎提示探索召唤、连锁、素材、对象和站位，并优先扩展当前探索中已走通的高分路线。最终用同一套规则给终场计分。

以一份本地的 SRVPro2 测试目录为输入。目录需要有可运行的 `dist/index.js`、`node_modules`、`ygopro`、`resource`、`data`、`Dialogs` 和 `cards.cdb`。WindBot 的 exe 使用放入本仓库覆盖文件后编译的版本。独立搜索使用测试目录内 SRVPro2 的卡库加载器、`koishipro-core.js` 和 `ygopro-msg-encode`，并使用本地的 `mono` 和 `mcs`。

```sh
python3 ygo-windbot/tests/compare_twins_planner.py \
  --fixture /path/to/srvpro2-test \
  --windbot /path/to/WindBot.exe \
  --output /tmp/twins-compare \
  --samples 20 --seed 20261123
```

`report.json` 记录起手、终场分、执行偏差、抽卡和站位。`summary.json` 汇总分差。用 `--from-case` 跳过前面的用例，用 `--max-gap 0.4` 设生产分差阈值。任何可比生产终场超过参考时，报告增加 `weak_references`，本次结果无法冻结。

整组结果满足冻结条件时，输出目录会生成 `references.json`，包含起手、牌序、阻抗条件、参考分和终场。复测用 `--reference-in /path/to/references.json`，仅运行生产策略并和固定终场比较。探索终场的引擎事件另存，复测直接读取终场和分数。

加上 `--search-matrix` 可跑 20 手定向对拍，覆盖小红、小蓝、甜心、初诣各搭配麻烦桑、口令句或合影，以及霜精、糖果或锻冶师。范围仍可用 `--from-case` 和 `--to-case` 分段运行。

每手的无坑和吃坑变体各有 10 秒参考搜索预算，可用 `--reference-ms` 增加。只有走完自己的回合并结算结束阶段的终场才参与排名。生产侧每次前台展开搜索的总预算上限为 5 秒，命中局面表或已有高分短连招时可提前返回。

### 手坑配对与固定参考终场

每种手坑随机抽三手能确认手坑实际落地的起手，每手各跑一局吃坑和无坑对照。两局使用相同的起手和牌序。覆盖第 5 次召唤吃陨石、镇魂棺吃灰、Link-1 吃天救龙、吃锁鸟、阿宝吃幽鬼兔、Link-2 吃泡影。天救龙展示五只同调、堆墓密码大师并破坏交易，密码大师另开连锁取另一只怪兽。报告记录对象以及初诣是否连锁。参考侧未找到满足手坑条件的候选记录在 `attempts.json`。参考侧找到有效路线后固定起手，生产侧避开手坑或未进入窗口的结果仍留在报告，标记为 `missed_interference`，同时保留该手的无坑对照。

```sh
python3 ygo-windbot/tests/compare_twins_interference.py \
  --fixture /path/to/srvpro2-test --windbot /path/to/WindBot.exe \
  --table ygo-windbot/Decks/AI_Twins.plan.jsonl --output /tmp/twins-interference

python3 ygo-windbot/tests/compare_twins_interference.py \
  --fixture /path/to/srvpro2-test --windbot /path/to/WindBot.exe \
  --table ygo-windbot/Decks/AI_Twins.plan.jsonl --output /tmp/twins-interference-retest \
  --reference-in /tmp/twins-interference/references.json
```

手坑配对的 `references.json` 仅在所选场景样本齐全、参考分达到已知下限及可比生产终场时写出。用 `--scenario` 单独生成或复测某种手坑。生成更多手牌时用新的输出目录。

仓库的 `fixtures/twins-interference-reference.json` 收录旧用例。通过 `--inputs-in` 读取其中的固定牌序并重新独立探索。该入口只取用例输入和明确的分数下限。小蓝＋双初诣＋G＋陨石这手的无坑下限为 10.7。报告中 `observed_gap` 是独立参考的实际差额，`target_score` 是验收要求，`unmet_targets` 记录参考未达到下限的用例。

`--wide-search` 可诊断 WindBot 内部宽搜，`--table-out`、五项开局 UT、对手回合和后攻主二测试仍使用原有实盘检查入口。这些诊断报告标识为 `legacy_wide_search`。对手回合妨碍分按终场可达动作计算。

加上 `--second --opponent-monster 14558128` 可让陪练先攻通召灰流丽，并把测试生命值设为 50000 以留出非斩杀战阶。脚本检查人机是否在解场后进入主二做场，同时记录承接的通召和效果使用状态。适合用固定用例核验战后交接。

加上 `--ash-trouble` 可使用录像中的人机起手，固定让陪练灰麻烦桑。报告里的 `first_action_ms` 从收到主一消息计时，`recoveries` 记录阻抗结算后重新规划的次数。

### 五项开局 UT

`--opening-ut` 一次运行五手固定起手。每手除了开局单卡，用四张手坑填满手牌。

| 起手 | 必须达到的终场或效果 |
| --- | --- |
| 单红、单蓝 | 额外区震怒、狮鹫、阿宝、夜幕、双陷阱。自己回合大红抽 1，对手回合震怒无效并送墓发动效果，再检查大红抽牌、大蓝炸卡、上镜无效。两手固定抽同一张牌。 |
| 单甜心 | 主怪兽区震怒、阿宝、夜幕、双陷阱。自己回合大红抽 1。对手回合阿宝实际苏狮鹫，震怒无效并自解，且大红抽牌、大蓝炸卡、上镜无效。 |
| 单红镇魂棺吃灰 | 狮鹫关箭头、阿宝、双陷阱，结束时霜精留在墓地。自己回合大红抽 1，对手回合大红抽牌、大蓝炸卡、上镜无效。 |
| 单甜心镇魂棺吃灰 | 双陷阱，自己回合大红抽 1，对手回合大红抽牌、大蓝炸卡、阿宝苏狮鹫。参考侧已实盘达成这些条件时，生产侧也可走实盘分更高的终场。 |

终场有可发动的阿宝，且手里有牌可弃时，阿宝炸卡可计 1 分。用苏生路线拿到更高分时，只计收益更高的那一项。

**单红、单蓝。** 单红通召拉小蓝，单蓝通召拉小红。两手都用小蓝做踩点并堆初诣，初诣解放踩点起跳拿口令句，小红第 5 次召唤做交易。这时小红和踩点在墓地，分别是合影的回收与苏生目标，口令句提供检索及费用。交易堆甜心，甜心自跳，交易做镇魂棺拉锻冶师。初诣和甜心做大蓝，大蓝苏交易。交易和锻冶师做神王，神王和大蓝做阿宝。口令句经麻烦桑拿合影。

单红线由阿宝苏小蓝拉霜精，单蓝线由阿宝苏小红拉小蓝。两手都做大红苏大蓝，大蓝炸麻烦桑触发神王苏踩点。锻冶师洗回交易起跳，与踩点做大圣棺。大红和大蓝做桑妮再拆回双子，大红抽 1。大圣棺用镇魂棺、桑妮和锻冶师融额外区震怒。大红和大圣棺做狮鹫，合影回收一只下级并除外麻烦桑苏大红。大红和大蓝做夜幕盖双陷阱，墓地大圣棺装备震怒，阿宝结束阶段回场。对手回合实测震怒无效并自解、大红抽牌、大蓝炸卡、上镜无效。单红额外保留墓地霜精，多 0.2 分。

有额外口令句时可沿用交易先行。第 5 次召唤出镇魂棺时，若口令句已能接合影的两个效果，保留 1 分防陨，并在同分时按通用防陨优先级优先这一方案。

**单甜心无阻抗。** 通召甜心做踩点，堆初诣并解放踩点起跳拿口令句。初诣做交易，交易先堆小蓝，甜心第 5 次召唤自跳。墓地有踩点和小蓝，口令句能接合影，计 1 分防陨。交易做镇魂棺，口令句经麻烦桑拿合影，镇魂棺拉锻冶师。甜心和锻冶师做大蓝，大蓝苏交易。锻冶师洗回镇魂棺起跳，与交易做神王，再用神王和大蓝做阿宝。

阿宝苏小蓝拉霜精，两只做大红，大红苏大蓝。大蓝炸麻烦桑，墓地神王苏锻冶师。双子做桑妮并拆回大红、大蓝，大红抽 1。双子做狮鹫，狮鹫和锻冶师做大圣棺。大圣棺用交易、桑妮和锻冶师融主怪兽区震怒。合影回收甜心落地，除外麻烦桑苏大红。大红和大圣棺做夜幕盖双陷阱，大圣棺从墓地装备震怒，阿宝结束阶段回场。优先把震怒放在中间主怪兽区，保留狮鹫苏生后的连接位置。对手回合实测阿宝苏回狮鹫、震怒无效并自解、大红抽牌、大蓝炸卡和上镜无效。

**单红镇魂棺吃灰。** 先踩点拿口令句，再由交易堆甜心，甜心起跳后开镇魂棺吃灰。口令句留到吃灰后再经麻烦桑拿合影。初诣和甜心直接做大红，大红苏回墓地的踩点。大红和踩点做大圣棺，融落泪苏大红，再和大圣棺做夜幕盖双陷阱。合影回收踩点落地，夜幕和落泪做神王，合影苏大红，神王和大红做阿宝。阿宝苏小蓝拉霜精，两只直接做大蓝，霜精入墓。大蓝苏大红抽 1，再做桑妮并拆回双子。大蓝炸麻烦桑，神王苏回桑妮，双子做狮鹫，阿宝回场。对手回合桑妮拆双子，挑战接上镜。

**单甜心镇魂棺吃灰。** 通召甜心做踩点，初诣解放踩点落地拿口令句。初诣做交易堆小蓝，甜心自跳，交易做镇魂棺。口令句经麻烦桑拿合影，开棺被灰。合影回收踩点落地，再除外口令句苏交易。甜心和交易做大红，大红苏甜心，两只做大圣棺。大圣棺融落泪苏大红，落泪和大红做神王，神王和大圣棺做阿宝。阿宝苏小蓝拉初诣，小蓝做踩点，踩点和初诣做大蓝。大蓝苏大红抽 1。做桑妮再拆双子，大蓝炸麻烦桑，神王苏桑妮。大红和大蓝做狮鹫，再用桑妮和狮鹫做上镜，把狮鹫留在墓地。上镜苏大红，两只做额外区夜幕盖双陷阱。对手回合挑战拉大蓝，大蓝苏大红，初诣解放大蓝接回双子效果。夜幕换交易，阿宝苏狮鹫。

之前的霜精分支也实盘达成过相同终场和对手回合断言。霜精留墓时多计 0.2 分，实盘为 6.7 分。

加上 `--single-twin-board` 会用单小红和单小蓝各带四张手坑起手。陪练在对手回合通召怪兽并发动魔法，报告检查震怒是否落在额外怪兽区、狮鹫、阿宝和夜幕是否同时在场、双陷阱是否盖放、自己回合大红是否抽牌，以及对手回合震怒是否先发动再送墓、大红、大蓝和上镜的三个效果是否结算。两手都要通过。用 `--check-opponent-turn --hand ...` 可以单独回放一手牌并记录同样的检查结果。

加上 `--ash-requiem` 会分别测试单小红、单小蓝和单甜心的刻魔镇魂棺吃灰。指定局面表时，两侧先使用同一条开棺前缀，再比较吃灰后的处理。前两手检查狮鹫不开放箭头、双陷阱、大红抽牌和对手回合大红、大蓝和上镜的三个效果，单小红还要求阿宝在场。报告记录额外区夜幕能否换成交易，并单列甜心是否能实现双陷阱、大红抽牌、对手回合大红大蓝和阿宝苏生狮鹫。如果离线参考已复现这套甜心终场，生产侧也可以用实盘分更高的终场通过。

对手回合报告还记录初诣是否解放大蓝、是否结算口令句检索，以及阿宝是否在检索结算后实际丢弃口令句。

霜精留在墓地且场上有邪恶双子时，条件抽牌计 0.2 分。同分比较会考虑能否保留合影。

狮鹫关住对手箭头、占一侧额外怪兽区且未指向另一侧时计 2.3 分。

镇魂棺线路计 1 分防陨时，镇魂棺必须从额外卡组在前五次召唤内做出，第 5 次召唤结算时手牌或墓地还要有能发动①的初诣。初诣需要保留本回合的效果次数、可解放的光或暗属性怪兽，以及解放后能用的主怪兽区。

合影的防陨判定独立计入同一个 1 分。合影可以已在手里，也可以经麻烦桑或口令句检索。墓地要同时有①能回收的对象、回收之后仍能被②苏生的邪恶双子，以及②的除外费用。检索过程中送入墓地的口令句也可以支付费用。

终场同分且两条路线都拿到防陨分时，依次优先前五次召唤内出镇魂棺且能接合影、只满足合影条件、只满足镇魂棺加初诣条件。第一种可由合影取得这 1 分，初诣没有第二次加分。

两条路线都拿不到防陨分时，终场同分仍优先前五次召唤内出镇魂棺。出棺时机本身不加分。

同分时，先比较检索次数，再比较把 Link-2 做成 Link-1 的次数、首次检索时机和防陨方案。两条路线终场都有凯撒时，接着优先更早做出凯撒。之后比较神王进墓地的时机。狮鹫场保留落泪之后，先比较终场是否多盖了挑战，再比较是否除外口令句。
规则单测可以用同一份 WindBot 和卡库执行。它覆盖单向连接的两端、指向空区、双方主怪兽区的箭头、额外区加分、融合和超量的落点，以及被狮鹫卡住的震怒不计分。

```sh
mcs -r:/path/to/WindBot.exe -out:/tmp/TwinsPlannerRules.exe ygo-windbot/tests/TwinsPlannerRules.cs
MONO_PATH=/path/to/windbot mono /tmp/TwinsPlannerRules.exe /path/to/cards.cdb
```

用 `--max-wait-ms 1000` 检查生产侧的等待。报告分别记录首动、单次规划峰值和本地陪练收到的主一、主二消息间隔。参考侧使用离线预算，耗时单独列出。

## 开局局面表

WindBot 默认使用局面连招和限时搜索。设置 `TWINS_PLAN_OPENING_TABLE=1` 后，才从运行目录的 `Decks/AI_Twins.plan.jsonl` 加载开局缓存。表命中时仍逐步核对引擎返回的合法动作。对手干扰、状态不匹配或表文件缺失时继续用限时策略。

表项由固定起手、随机起手和麻烦桑吃灰的实盘生成。键保留场上位置、额外区域限制、可用牌、墓地和已用效果。吃灰后的局面使用单独的键。只有在展开中充当可弃牌的手坑可以共用分类，能盖放的泡影等卡仍然单列。

```sh
python3 ygo-windbot/tests/compare_twins_planner.py \
  --fixture /path/to/srvpro2-test --windbot /path/to/WindBot.exe \
  --output /tmp/twins-table-train --seed 20261125 \
  --hand 82699999,42141493,42141493,27204311,59438930 \
  --table-out /tmp/AI_Twins.plan.jsonl

python3 ygo-windbot/tests/compare_twins_planner.py \
  --fixture /path/to/srvpro2-test --windbot /path/to/WindBot.exe \
  --output /tmp/twins-table-check --samples 0 --to-case 0 \
  --table /tmp/AI_Twins.plan.jsonl
```

生成脚本只导出离线参考实盘走通的路线。合并多次跑出的表时，同键优先保留已验证的高分路线，并用合并后的表复测。记录包含命中数、搜索节点数和实盘分。卡效或计分规则变更后，重新生成并复测表项。

## 局面连招策略

连招策略由 WindBot 根据当前场上、手牌、墓地、卡组和已用效果决定。策略只提出当前资源能支持的续展动作。素材、目标和区域由同一套合法动作生成逻辑验证，站位及终场按妨碍评分选择。同一段连招可用于不同起手或手坑结算后的局面。

每段只列展开需要的资源、场上配置和未用效果。交易堆甜蜜的入口检查甜蜜仍在牌组且未上手。开棺后，场上初诣、甜蜜和锻冶师，墓地有可苏生的交易，大蓝苏生未用且额外还有大蓝、神王和阿宝时，可先做大蓝、苏交易、做神王和阿宝。口令句和多余手牌可以保留到阿宝落地。初诣起跳会按计划区分手牌和墓地的副本。

踩点保留堆初诣的路线。手牌或墓地已有能起跳的初诣、且霜精还未进墓时，展开可比较踩点堆霜精的终场。固定对拍中小蓝加双初诣的无坑对照因此从 10.5 提升到 10.7 分。

单次前台规划预算为 5 秒。短连招先评估，常规搜索和后半段补全共用剩余时间。桑妮已经拆出大红、大蓝时，只要大圣棺和融合素材就绪，仍可从该局面接回震怒和夜幕双盖。

自己回合的抽牌在连锁结算后触发一次短检查。规划器用实盘手牌和已用效果重评原计划的余下动作，再限时查找分数更高的终场。同分时也可以改走能多盖挑战或更早做出凯撒、且符合通用同分优先级的路线。日志 `draw-replan` 记录原计划得分、新候选得分、是否换线和用时。抽走原计划依赖的最后一张卡时，仍走原来的库存变化重规划。

传入 `--table` 会为对拍开启整手开局缓存。省略 `--table` 可单独验收默认策略。报告中的 `tactical_hits` 记录选用局面连招策略的次数。

```sh
python3 ygo-windbot/tests/compare_twins_planner.py \
  --fixture /path/to/srvpro2-test --windbot /path/to/WindBot.exe \
  --output /tmp/twins-state-tactics --single-twin-board \
  --max-gap 0.4 --max-wait-ms 3000
```
